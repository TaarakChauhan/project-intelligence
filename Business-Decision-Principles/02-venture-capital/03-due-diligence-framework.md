# VC due diligence framework

**Purpose:** Test claims proportionately across the main risk domains.

**Who this is for:** VCs, angels, founders, and diligence workstream leads.

## Core principles
1. Start with the investment thesis and list the claims that must be true.
2. Cover financial, commercial/market, product/technology, team, legal, and ESG/reputation risks where material.
3. Prefer primary evidence: bank statements, contracts, cohort exports, customer calls, source code review, references, and filings.
4. Triangulate; one impressive data point is not a system.
5. Record open items, materiality, owner, and resolution—not just a folder of documents.

## How decisions actually get made
For each claim write: evidence supporting, evidence contradicting, confidence, downside if false, and next test. Match depth to stage and cheque size. Protect confidentiality and data security. Legal or technical specialists should advise on their scope rather than rubber-stamp the entire deal.

## Worked mini-example
Claim: “Customers love the product.” Test usage by cohort, renewal/expansion, support burden, customer concentration, and calls with both retained and churned accounts. If only the founder-selected references are enthusiastic, confidence stays low.

## Common mistakes
- Accepting a polished data room without checking source systems.
- Treating a customer reference as representative.
- Forgetting IP assignment, employment, privacy, or regulatory issues.
- Overlooking ESG or reputation risks because the company is early.

## Practice exercise (15 minutes)
Pick three claims in a hypothetical company. Build an evidence table with source, independent corroboration, unresolved question, and consequence if wrong.
